# SkillHub 模拟黑客松：产品范围

更新日期：2026-09-25
当前阶段：核心流程与最小演示范围

## 最新产品方向（2026-09-26）

SkillHub 聚焦 Skills 的分享与交流。Agent 不再作为可发布、浏览、管理或关联的作品类型；论坛、知识库和专题仅允许新增 Skill 关联。历史帖子、回复、关联记录、通知和上传文件均保留，旧关联标记为“关联的 Agent 已停止展示”，不自动改绑到 Skill。网站内部的自动审核 Agent 和 AI 助手继续运行。

本节为当前有效决策；以下早期产品范围和过程记录保留为项目历史，不再代表现行方向。

- 用户认可让帖子关联作品，并通过通知让已入驻的作者或关注者有机会回应。

## 核心使用流程

1. 作者提交作品介绍及可访问的使用入口。
2. 使用者在 SkillHub 浏览或搜索作品。
3. 使用者查看用途、示例和使用条件，判断是否适合自己的任务。
4. 使用者通过作品链接，前往作者提供的平台使用。
5. 使用者回到该作品关联的讨论中提问或分享经验。
6. 作者或其他成员回复，后续使用者可以参考这些讨论。

## 第一版设计建议（待继续讨论）

- 发布作品：填写名称、用途、来源平台和使用链接；补充使用说明、效果示例及必要的使用条件。作者有模板或源码时，可提供对应入口。
- 发现作品：提供作品列表、搜索和详情页，详情页明确展示“去使用”的目的地。
- 作品交流：论坛帖子可关联具体作品；作品详情页展示相关讨论，并提供发帖入口。
- 论坛优先用途已确认：使用求助和实践经验分享。是否同时支持独立于作品的一般讨论，后续确定。
- 演示目标：完整展示一次作品发布、被发现、跳转使用、关联提问和回复的过程。

## 本次比赛的最小演示方案（建议）

用一个 Agent 作品贯穿主线：作者发布作品 → 使用者搜索发现 → 查看详情并前往原平台使用 → 回站提交关联求助 → 作者收到通知并回复 → 提问者反馈解决结果。

另演示一次经验帖发布，确认 Skill 和 Agent 都可以关联帖子，读者可以从帖子回到对应作品。

| 功能 | 演示时应能完成的操作 |
|---|---|
| 发布作品 | 作者保存作品介绍及使用入口，发布后在前台可发现 |
| 发现作品 | 使用者通过列表或搜索找到作品，进入详情 |
| 判断并使用 | 使用者查看用途、示例、必要使用条件，打开作者提供的链接 |
| 发起交流 | 从作品详情发起求助或经验帖，自动带入作品关联；帖子能回到作品 |
| 接续讨论 | 作者收到提醒、回复问题；提问者查看回复并反馈结果；后续用户能读到讨论 |

拟涉及页面：作品列表、作品详情、作品发布表单、论坛列表、发帖表单、帖子详情。通知入口衔接帖子详情。

下一项设计决策：首次访问的主要入口如何安排作品发现与论坛内容。初步建议作品列表为主入口，作品详情呈现关联讨论，同时保留独立论坛入口。

## 现有项目对照（2026-09-25 源码核对）

下列结论来自本地代码；运行效果和线上版本尚未在本轮实测。后续页面设计应基于这些现有页面调整。

| 环节 | 本地现有实现 | 与目标流程的差距 |
|---|---|---|
| 作品发布与发现 | 有 Skill 发布/下载，以及 Agent 发布、搜索、分类和框架筛选 | Agent 发布把源码仓库和运行入口合为一个字段，需明确不同链接的用途 |
| Agent 使用入口 | 详情有下载包或“查看仓库 / 运行入口”按钮 | 提供文件包时只优先展示下载入口；需让在线使用与获取材料各自清晰 |
| 作品详情与论坛 | Agent 详情仅显示论坛帖子数量；Skill 详情没有关联讨论区域 | 需展示可访问的相关帖子，并提供带作品关联的发帖入口 |
| 发帖 | 已有讨论、问题、结构化案例三类表单 | 当前前台表单没有选择或自动带入关联作品的流程；需复用现有能力完善求助与经验帖体验 |
| 帖子关联作品 | 帖子详情已展示关联 Skill / Agent；后台有添加关联的操作 | 关联能力需接入普通用户发帖流程及作品详情反向展示 |
| 回复与通知 | 已有回复、采纳答案、通知列表和通知跳转帖子 | 需核对作品作者收到新关联帖通知的规则，不能据通知页面存在认定该规则已完成 |
| Skill 兼容性 | 当前发布/详情相关源码未见 compatibility 字段 | 按 SKILL-001 增加可选兼容性说明 |

优先改动建议：先补齐“作品详情 → 带关联发帖 → 回复 → 回到作品”的路径，再调整 Agent 的使用链接展示。
